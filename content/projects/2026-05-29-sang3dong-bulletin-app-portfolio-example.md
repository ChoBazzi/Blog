## 프로젝트 개요

상3동성당 주보앱은 매주 배포되는 종이 주보를 모바일에서 확인할 수 있도록 만든 개인 프로젝트입니다. 단순히 PDF를 앱에 넣는 것이 아니라, 사용자가 앱을 열었을 때 최신 주보를 빠르게 찾고 읽을 수 있는 흐름을 목표로 했습니다.

- 기간: 2023-08 ~ 2023-10
- 구분: 개인 프로젝트
- 역할: 기획, 모바일 앱 개발, 백엔드 개발, 배포, 운영
- 주요 기술: React Native, JavaScript, Django, Python
- 결과: Google Play Store 출시, 실사용자 130명 확보
- 링크: [Play Store](https://play.google.com/store/apps/details?id=com.sang3dong)

![상3동성당 주보앱 화면](/projects/sang3dong-bulletin-app/portfolio.jpg)

## 문제

성당 소식은 매주 종이 주보를 통해 전달되고 있었습니다. 하지만 종이 주보는 미사에 참석한 뒤 직접 챙겨야 확인할 수 있었고, 젊은 교우나 주보를 놓친 사람에게는 접근성이 낮았습니다. 인쇄 비용과 자원 낭비도 계속 발생했습니다.

저는 이 문제를 "주보를 디지털로 바꾸자"가 아니라, "성당 소식을 필요한 순간에 다시 확인할 수 있게 하자"는 접근성 문제로 정의했습니다. 그래서 앱의 첫 목표는 많은 기능을 넣는 것이 아니라 최신 주보를 안정적으로 보여주는 것이었습니다.

## 제약

이 프로젝트는 혼자 진행했기 때문에 기획, 개발, 배포, 운영을 모두 직접 처리해야 했습니다. 기능을 넓히기보다 출시 가능한 최소 범위를 정하고, 실제 사용자가 반복해서 쓸 수 있는 흐름을 먼저 완성해야 했습니다.

주요 제약은 다음과 같았습니다.

- 모바일에서 PDF 주보를 안정적으로 열어야 함
- 사용자가 앱을 열면 최신 주보에 빠르게 접근해야 함
- 백엔드 운영 비용과 관리 부담을 낮춰야 함
- Play Store 심사와 배포까지 혼자 처리해야 함
- 사용자가 개발자가 아니므로 오류 상황을 복잡하게 보여주면 안 됨

## 해결 방향

처음부터 성당 생활 전체를 다루는 앱을 만들기보다, v1에서는 주보 확인 문제에 집중했습니다. 기능 범위를 좁히면 배포까지 갈 가능성이 높아지고, 실제 사용자의 반응을 빠르게 확인할 수 있다고 판단했습니다.

전체 흐름은 다음과 같이 나누었습니다.

```text
관리/수집 단계
  -> Django Backend
  -> 주보 데이터 정리
  -> 모바일 앱에서 조회 가능한 형태로 제공

사용자 단계
  -> React Native App 실행
  -> 최신 주보 확인
  -> PDF 주보 열람
```

프론트엔드는 React Native로 구현했습니다. 성당 교우들이 사용하는 기기가 다양할 수 있기 때문에, Android 앱으로 배포 가능한 모바일 구조가 필요했습니다. 주보 파일은 PDF 형태였기 때문에 React-Native-PDF를 사용해 앱 안에서 바로 열람할 수 있도록 구성했습니다.

백엔드는 Django와 Python으로 구성했습니다. 앱이 직접 복잡한 데이터를 처리하기보다, 서버가 주보 데이터를 관리하고 모바일 앱은 필요한 형태로 받아보는 구조가 유지보수에 더 적합하다고 판단했습니다.

## 구현

모바일 앱에서는 사용자가 앱을 열었을 때 최신 주보에 바로 접근할 수 있는 흐름을 우선했습니다. 주보 앱의 핵심 사용자는 글을 오래 탐색하는 사람이 아니라, 이번 주 주보를 빠르게 확인하려는 사람이라고 보았기 때문입니다.

백엔드에서는 주보 데이터를 관리하고 앱에서 사용할 수 있는 형태로 제공했습니다. 일부 데이터 수집과 정리에는 Cheerio를 활용했습니다. 이 과정에서 모바일 앱이 데이터 출처나 정리 방식에 직접 의존하지 않도록 역할을 나누었습니다.

배포 과정에서는 Play Store 등록까지 직접 진행했습니다. 앱 패키징, 스토어 등록 정보 작성, 심사 대응, 배포 후 사용자 반응 확인까지 경험하면서 개발 이후의 운영 과정도 프로젝트 범위에 포함했습니다.

## 트레이드오프

가장 큰 선택은 기능 범위를 좁히는 것이었습니다. 공지, 일정, 알림, 미사 정보까지 한 번에 넣으면 앱의 가치가 커질 수 있지만, 첫 버전에서 모든 기능을 안정적으로 운영하기는 어려웠습니다.

그래서 v1에서는 주보 확인에 집중했습니다. 이 선택은 앱의 첫 사용 경험을 단순하게 만들었지만, 성당 생활 전반을 다루는 앱으로 보기에는 기능이 부족하다는 한계도 남겼습니다. 이 한계는 이후 v2에서 주보, 전례력, 미사 정보, 본당 소식을 함께 다루는 방향으로 확장할 수 있는 근거가 되었습니다.

또 다른 선택은 PDF 기반 열람을 유지한 점입니다. 주보 내용을 구조화된 데이터로 바꾸면 검색이나 접근성 개선에 유리하지만, 운영 부담이 커집니다. 당시에는 빠른 출시와 안정적인 열람이 더 중요했기 때문에 PDF를 그대로 보여주는 방식을 선택했습니다.

## 검증과 결과

이 프로젝트는 Google Play Store에 출시했고, 실사용자 130명을 확보했습니다. 개인 프로젝트가 로컬에서 끝나지 않고 실제 사용자가 설치하고 사용하는 서비스가 되었다는 점에서 의미가 있었습니다.

사용자에게 받은 "덕분에 편리하다"는 피드백은 기능의 크기보다 실제 생활의 불편을 줄이는지가 더 중요하다는 것을 확인하게 해주었습니다. 특히 성당처럼 특정 공동체 안에서 쓰이는 앱은 대규모 트래픽보다 반복 사용성과 신뢰가 더 중요했습니다.

## 아쉬웠던 점

v1은 최신 주보를 보는 문제에는 집중했지만, 성당 소식을 한곳에서 확인하는 앱으로는 부족했습니다. 미사 시간, 전례력, 본당 공지처럼 사용자가 반복적으로 확인할 수 있는 정보가 함께 제공되었다면 앱을 더 자주 열 이유가 생겼을 것입니다.

또한 PDF 중심 구조는 빠르게 출시하기에는 좋았지만, 장기적으로는 콘텐츠를 세밀하게 다루기 어렵습니다. 주보 안의 일정이나 공지를 앱 화면에서 바로 탐색하려면 PDF 열람을 넘어 구조화된 데이터 관리가 필요합니다.

## 배운 점

이 프로젝트를 통해 개인 프로젝트도 문제 정의가 구체적일수록 완성 가능성이 높아진다는 것을 배웠습니다. "성당 앱을 만들자"가 아니라 "놓친 주보를 모바일에서 다시 볼 수 있게 하자"로 범위를 좁혔기 때문에 기획부터 배포까지 끝낼 수 있었습니다.

또한 앱 개발은 코드 작성으로 끝나지 않는다는 점을 체감했습니다. 배포, 심사, 사용자 피드백, 운영 부담까지 고려해야 실제 사용자가 쓰는 서비스가 됩니다.

다음 버전에서는 v1의 단순함은 유지하되, 주보 중심 앱을 성당 생활 허브로 확장하는 방향을 고민하고 있습니다. 핵심은 기능을 많이 넣는 것이 아니라, 사용자가 오늘 필요한 성당 정보를 빠르게 찾게 만드는 것입니다.
