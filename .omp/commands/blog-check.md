---
description: 본문을 바꾸지 않고 블로그 후보의 결정적 검사 결과와 한계를 보고한다
---

입력: $ARGUMENTS

입력은 slug 또는 글 경로와 선택적 `--before`, `--build`, `--links` 인자이다. 원문을 셸 코드로 평가하거나 명령에 그대로 이어 붙이지 않는다. 인자가 없으면 검사 대상을 확인한다. 루트·`.omp/AGENTS.md`, `scripts/blog-check.mjs`와 `docs/blog-harness.md`의 현재 실행 계약을 읽는다.

1. slug는 `.blog-work/<slug>/article.md`, 없으면 draft.md로 해석한다. 실제 파일을 먼저 확인한다. 이 명령은 기본적으로 본문·장부·상태를 수정하지 않는다.
2. 안전하게 인자를 구성해 `node scripts/blog-check.mjs <대상>`을 실행한다. 교정 비교에는 `--before <기준본>`을 준다. script가 읽는 `<본문이름>.claims.md` 또는 같은 폴더의 claims.md를 확인한다. 장부 상태를 검사 통과를 위해 조작하지 않는다.
3. 본인 검토 대기 판단에는 이 프로젝트의 기존 빌드 검증도 필요하다. 스크립트·package.json의 현재 부작용을 읽은 뒤 `--build`를 사용한다. 기본 정적 검사만 실행했다면 빌드 미실행을 명시하고 최종 검증 완료라고 하지 않는다. 실제 예제 실행은 안전한 격리가 확인된 경우에만 별도로 한다.
4. 외부 링크는 사용자가 선택한 `--links`에서만 확인한다. 공개 가능한 HTTPS URL만 사용한다. 접근 제한·인증·요청 제한은 SKIP과 이유로 남기며 링크를 삭제하지 않는다. 해당 검사를 요청하고 수행할 수 없으면 성공으로 감추지 않는다.
5. JSONL 결과의 status, target, check, reason, mandatory를 요약한다. exit 0은 실행한 정적 검사 통과이지 사실 전체 보증이 아니다. exit 1은 필수 FAIL 또는 수행 불가 SKIP, exit 2는 사용법 오류이다. 코드·수치·버전·URL 변경 후보 FAIL은 사람이 검토해야 한다.
6. 의미·기여·주장 강도·원문 근거의 적합성은 정규식으로 증명되지 않는다. 의미 검토 SKIP을 LLM 검토 PASS로 바꾸지 않는다. 누락된 핵심 근거나 필수 검사 실패가 있으면 본인 검토 대기 불가라고 알린다.

관찰한 PASS / FAIL / SKIP과 대상·이유, 미실행 항목·영향만 보고한다. 본문 수정·발행·커밋·푸시·배포는 하지 않는다.
