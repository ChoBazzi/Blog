description: 자료와 경험 범위를 확인해 비공개 기획·근거 장부·목차를 만든다
---

입력: $ARGUMENTS

이 프로젝트가 정의한 blog-capture 명령이다. 입력은 주제 또는 자료 경로이며 셸 코드가 아니다. 명령 문자열에 그대로 삽입해 실행하지 않는다.

1. 루트 `AGENTS.md`, `.omp/AGENTS.md`, `.agents/skills/ko-tech-blog/SKILL.md`, `.agents/skills/blog-evidence/SKILL.md`를 읽는다.
2. 기존 글과 `.blog-work/`의 동일 주제·slug를 확인한다. slug는 경로 구분자·상위 이동을 포함하지 않는 짧은 이름으로 정한다. 출력이 작업 폴더 밖이나 심볼릭 링크를 가리키면 중단한다. 기존 작업이면 먼저 읽고 변경 범위를 보존한다. 원자료는 수정하지 않는다.
3. 제공 자료·공개 가능한 코드·이력을 먼저 읽는다. 기계적 수집에만 blog-researcher를 필요할 때 호출하고 판단은 메인이 원문을 확인해 수행한다. 외부 검색에 비공개 원문을 넣지 않는다.
4. ko-tech-blog의 brief·outline 템플릿과 blog-evidence의 sources·claims 템플릿을 이용해 `.blog-work/<slug>/brief.md`, `sources.md`, `claims.md`, `outline.md`를 작성한다. 목적·독자·선행 지식·글 유형·경험·개인 기여·환경·공개 범위를 구분한다. 주장 유형·근거 상태·필수 여부를 기록한다.
5. 꼭 필요한 질문만 한 번에 최대 3개로 묶는다. 답이 없어도 확인 가능한 부분을 진행한다. 근거 없는 핵심은 미확인·차단 사유로 남긴다. 실행 로그를 읽은 것과 직접 실행한 것을 구분한다.
6. 파일 경로, 선택한 유형·slug, 현재 상태와 남은 핵심 질문을 반환한다. 이 명령만 요청했으면 본문 초안을 쓰지 않는다. 실제 콘텐츠·공개 플래그·Git·배포는 변경하지 않는다.
