description: 기술·독자 검토와 한국어 교정 후 재검증해 비공개 후보를 만든다
---

입력: $ARGUMENTS

입력은 slug 또는 초안 경로이며 셸 코드가 아니다. 루트·`.omp/AGENTS.md`, ko-tech-blog, blog-evidence, k-humanizer 스킬을 읽는다. 외부 경로의 초안은 원본을 유지하고 `.blog-work/<slug>/`에서 작업한다. 기존 후보·기록을 읽고 보존한다.

1. brief·sources·claims·outline·draft를 읽는다. 부족한 근거는 capture 절차로 정리하고 핵심 미확인 사항을 꾸며 채우지 않는다. 상태를 검토 중으로 기록한다.
2. 필요한 역할만 읽기 전용으로 호출한다. blog-tech-reviewer에는 초안과 근거·버전·실행 기록을 제공한다. 장문 설계·튜토리얼에는 blog-reader도 호출한다. reader의 새 컨텍스트에는 **초안 + 독자 + 선행 지식만** 전달한다. 작성 대화·장부·메인 해설·정답은 보내지 않는다. 실제 최소 컨텍스트·도구 제한을 확인하지 못하면 독립 검토 SKIP으로 기록한다.
3. 검토자는 파일을 수정하지 않고 위치·문제·근거·제안을 반환한다. 메인이 ko-tech-blog의 review 템플릿을 사용해 review.md에 결과와 반영 이유를 기록한다. 사실 오류·근거 부족·취향 제안을 구분하고 특이사항 없음을 허용한다.
4. 한국어 교정은 blog-ko-editor 또는 메인이 k-humanizer 규칙으로 수행한다. 수정본·변경 이유를 남긴다. 큰 구조 변경은 작성 단계로 돌린다. draft를 기준본으로 보존하고 수정 후보를 article.md에 둔다. 모두 비공개이고 published는 false이다.
5. 코드·수치·버전·URL 차이는 `node scripts/blog-check.mjs <후보 경로> --before <기준본 경로>`로 확인한다. 실제 경로는 인자로 안전하게 전달한다. 주장 강도·인과·조건·기여는 메인이 근거와 다시 읽어 대조한다. 차이 FAIL은 자동 승인하지 않고 이유를 검토 기록에 남긴다.
6. blog-check 절차로 필수 검증과 검토한 기존 빌드를 수행한다. 안전하지 않은 예제는 실행하지 않고 필수 검증 수행 불가로 기록한다. 정적 검사와 실제 LLM 실행 결과를 분리한다.
7. 검토·수정은 기본 최대 2회이다. 핵심 미확인·충돌 또는 필수 검증 실패·수행 불가가 남으면 상태는 차단됨이다. 모두 해소되었을 때만 본인 검토 대기이다. 비핵심 SKIP은 이유·영향을 적는다. 후보가 있어도 완료를 가장하지 않는다.

파일 경로, 상태, 실제 PASS / FAIL / SKIP, 남은 문제와 작성자 확인 사항을 반환한다. 본인 검토 대기는 발행 승인이 아니다. 공개 경로 이동·플래그 변경·커밋·푸시·배포·플랫폼 API 호출을 하지 않는다.
