# 설계 결정 구성 템플릿

완성 글이 아닌 작성 안내이다. 초안 생성 시 지시문을 근거 있는 본문으로 대체하고 [문체 지침](../style-guide.md)의 frontmatter를 추가한다. 해당하지 않는 선택 절은 생략한다.

## 요구사항과 제약

해결할 질문, 선택 결과의 요약, 독자가 얻을 내용을 앞에 놓는다. 당시 요구사항·환경·시간·인력 제약을 자료가 확인해 주는 범위에서 기록한다. 사후 평가는 구분한다.

## 비교한 대안

실제로 검토한 대안과 비교 기준을 적는다. 써 보지 않은 대안은 실행 검증한 것처럼 쓰지 않는다. 비교 대상의 버전과 조건을 맞추고 공식 자료를 관련 주장 옆에 연결한다.

## 선택과 근거

무엇을 선택했고 왜 해당 제약에서 타당했는지 설명한다. 당시 메모·ADR와 작성자의 현재 설명을 구분한다. 코드의 존재로 선택 이유를 추정하지 않는다. 팀의 결정과 개인의 제안·구현·검토를 나눈다.

## 감수한 비용

얻은 이점뿐 아니라 포기한 특성, 복잡성, 유지보수·운영 제약을 확인된 범위에서 설명한다. 예상 비용과 실제 측정 비용을 구분한다.

## 재검토 조건

어떤 조건이 달라지면 선택을 다시 검토해야 하는지 기술적 판단과 근거를 제시한다. 숫자가 없으면 임의의 전환 임계값을 만들지 않는다. 장문이면 독자 검토에 초안·독자·선행 지식만 전달한다.
